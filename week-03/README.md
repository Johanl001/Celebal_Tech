📌 Overview : 
This notebook builds a complete, production-style Machine Learning pipeline that turns an **unsupervised** problem into an end-to-end **Customer Intelligence System**. It applies the industry-standard *cluster-then-classify* pattern: entities are first segmented using unsupervised clustering (K-Means, DBSCAN), the resulting segments are profiled and named in business-readable terms, and supervised classifiers (Random Forest, XGBoost) plus a soft-voting ensemble are then trained to predict segment membership for new, unseen entities — without needing to re-run clustering on the whole dataset every time.

The pipeline is built on country-level socio-economic data as a stand-in for customer data (same features, different labels — `country` → `customer_id`, GDP/health/income → behavioral or spend features), so the methodology transfers directly to a real CRM use case.

🔄 Pipeline Stages

| # | Stage | Description |
|---|---|---|
| 1 | Data Ingestion & Inspection | Load dataset, check dtypes, shape, null audit |
| 2 | Exploratory Data Analysis | Correlation heatmap, feature distributions |

🏷️ Feature Engineering / Segment Design
No new raw features were engineered (the dataset is already a compact set of macro indicators); instead, the "engineering" happens at the **label level**:

| Artifact | Formula / Logic | Rationale |
|---|---|---|
| `segment` | K-Means cluster ID on scaled features | Unsupervised target for the classifiers |
| `segment_name` | Clusters ranked by mean `gdpp`, mapped to tiered labels | Turns opaque cluster IDs into a business-readable output |
| DBSCAN noise flag | `label == -1` | Surfaces outlier entities (e.g. distorted small-economy GDP figures) worth a manual look |

🤖 Models Used

| Model | Type | Notes |
|---|---|---|
| K-Means | Clustering (centroid-based) | *k* selected via silhouette score, not guessed |
| DBSCAN | Clustering (density-based) | Tuned via grid search over `eps`/`min_samples`; used as a validation/outlier pass against K-Means |
| Random Forest | Ensemble (bagging) | 300 estimators, tuned via `GridSearchCV` |
| XGBoost | Ensemble (boosting) | Tuned via `GridSearchCV` over depth/learning rate |
| Voting Ensemble | Ensemble (soft voting) | Averages RF + XGBoost predicted probabilities |

All classifiers evaluated on: **Accuracy, Precision, Recall, weighted F1, 5-fold CV F1 (mean ± std)**

📈 Cluster Validation
- **Silhouette score** and **Davies-Bouldin index** used to pick the number of K-Means clusters objectively, rather than assuming a fixed *k*.
- **DBSCAN grid search** run across a range of `eps`/`min_samples` combinations; the noise percentage at each setting indicates how well density-based clustering fits this dataset (high noise % across most settings signals K-Means is the better primary choice here).
- **Adjusted Rand Index (ARI)** between K-Means and DBSCAN labels quantifies whether two structurally different algorithms agree — high agreement is evidence the segments reflect genuine structure rather than an artifact of one algorithm's assumptions.

📋 Evaluation Metrics

| Metric | Formula / Definition | Interpretation |
|---|---|---|
| Silhouette Score | Mean (b − a) / max(a, b) per point | Cluster cohesion & separation; closer to 1 is better |
| Davies-Bouldin Index | Avg. similarity of each cluster to its most similar cluster | Lower is better (less overlap) |
| Adjusted Rand Index | Agreement between two label sets, corrected for chance | 1.0 = perfect agreement, 0.0 = random |
| Accuracy | Correct predictions / total predictions | Can be misleading with unequal segment sizes |
| Weighted F1 | Harmonic mean of precision & recall, weighted by segment size | Primary metric used for model comparison here |
| CV-F1 (mean ± std) | F1 across 5 folds | Std dev indicates model stability, not just average performance |
| Paired t-test | Statistical test on paired CV fold scores | Confirms whether one model's edge over another is real or noise |
